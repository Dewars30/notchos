The hook mechanism is public and simple. Claude Code's hooks in `~/.claude/settings.json`:

The hook receives a JSON payload on stdin with the tool name, input, and session info. That's the entire integration layer.

My recommendation for you: Option B (Tauri). You get a real GUI in React/Tailwind, you already think in that stack, Rust handles the socket with 10 lines, and the output is a distributable `.app`. Want me to scaffold the Tauri project with the Claude Code hook receiver and a basic approval UI?

```json
{
  "hooks": {
    "PreToolUse": [{ "matcher": "", "hooks": [{ "type": "command", "command": "your-binary event pre-tool" }] }],
    "PostToolUse": [{ "matcher": "", "hooks": [{ "type": "command", "command": "your-binary event post-tool" }] }]
  }
}
```

1. Hooks — writes entries into Claude Code's settings.json, Codex's hooks.json, etc. so those tools POST events to a local Unix socket on every action (file edit, permission request, completion)
2. Bridge binary — lightweight process that listens on that socket and normalizes events
3. Notch UI — a native Swift overlay that renders in the menu bar / notch area, shows agent status, and surfaces approval buttons
4. Terminal jump — AppleScript/accessibility APIs to focus the right iTerm2 tab

## Assistant

Functionally, three things:

1. The notch itself. The Dynamic Island aesthetic — UI literally living inside the notch cutout — requires Swift + specific `NSWindow` positioning against `NSScreen`'s notch frame. Tauri's WebView can't render there. You get a floating bar at top-center instead. It works, looks fine, but it's not in the notch.

2. Precise terminal jump. iTerm2's deep jump (specific split pane, specific tmux session) uses AppleScript and iTerm2's proprietary RPC. Tauri can shell out to AppleScript, so you can get app-level focus and basic tab matching — but the "jump to exact pane" behavior requires more brittle scripting. Ghostty's precise jump uses a socket protocol that's also doable but manual work.

3. Native feel. The notch panel in Vibe Island animates with system-native transitions, respects macOS appearance modes without WebView quirks, and has no render jank. A Tauri WebView is close but you'll fight occasional frame artifacts and the window chrome is slightly off unless you go fully frameless and nail the CSS.

What you're NOT losing:

Honest take: If you're building this purely for your own workflow, Tauri gets you 90% of the value in 20% of the time. The notch is a party trick — you'll stop noticing it after a week. The real value is the approval surface and not context-switching, which Tauri delivers fully.

If you ever wanted to ship this as a competing product, you'd need Swift for the notch to have a credible differentiator. But that's a different conversation.

Tauri or not?

- The hook integration — identical, it's just JSON config + stdin parsing
- Approval UI — yours could be better since you control the React
- Multi-agent monitoring — same capability
- Sound alerts, plan review, session history — all buildable
- Performance — Tauri is actually lighter than Vibe Island in practice
